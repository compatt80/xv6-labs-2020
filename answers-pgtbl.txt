Q1: 解释为什么在 copyin_new() 中需要第三个测试 `srcva + len < srcva`。
A1: 这个测试是为了防止整型溢出攻击。举个例子，假设当前进程的内存大小 `p->sz` 为 0x1000。如果恶意用户传入合法的起始地址 `srcva = 0x100` 和极大的长度 `len = 0xFFFFFFFFFFFFFFFF`，相加后会发生 64 位整型溢出，回绕变成 `0xFF`。
- 第一个测试 (`0x100 >= 0x1000`) 结果为假，绕过成功。
- 第二个测试 (`0xFF >= 0x1000`) 结果为假，再次绕过成功。
如果没有第三个测试，这个恶意的巨大长度就会骗过系统检查。而第三个测试会严格判断 `0xFF < 0x100`，结果为真，从而成功拦截这种溢出攻击并返回 -1。

Q2: 根据图 3-4 解释 vmprint 的输出。page 0 包含什么？page 2 中是什么？在用户模式下运行时，进程是否可以读取/写入 page 1 映射的内存？
A2: 
- Page 0 包含用户程序的代码段和数据段。
- Page 2 包含用户进程的栈。
- 不可以。Page 1 充当了保护页的作用，内核在分配时清除了它的访问权限。如果用户程序的栈由于无限递归等原因疯狂向下生长并试图访问 Page 1，硬件会立刻触发页面错误并杀死进程，从而防止栈溢出悄悄覆盖掉 Page 0 里的核心代码。
